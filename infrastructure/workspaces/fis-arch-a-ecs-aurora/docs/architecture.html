Architecture A — FIS Chaos Scenarios

CloudFront (VPC Origin) · Internal ALB · ECS Fargate · Aurora PostgreSQL  |  4 シナリオ

A-1

Aurora Cluster Failover

aws:rds:failover-db-cluster

リーダーをライターに昇格させ、アプリケーションがクラスターエンドポイントを通じて再接続できるかを検証。コネクションプールのリカバリ時間と再試行ロジックを確認する。

⏹ Stop: Aurora接続数がほぼ0になるCWアラーム

A-2

ECS Task 全停止

aws:ecs:stop-task

タグ fis-target=app-service が付与されたECSタスクを全停止。ECS Serviceの自動復旧速度と、CloudFrontがS3エラーページへフォールバックする動作を検証する。

⏹ Stop: ALB 5xx > 50/分 CWアラーム

A-3

DB ポート Egress ブラックホール

aws:ecs:network-blackhole-port

ECSタスクからポート5432へのTCP egress を遮断。Auroraへの完全な接続喪失をシミュレートし、アプリケーションのエラーハンドリングとタイムアウト設定を検証する。

⏹ Stop: ALB 5xx > 50/分 CWアラーム

A-4

HTTP ポート Ingress ブラックホール

aws:ecs:network-blackhole-port

ECSタスクへのポート80 TCP ingress を遮断。ALBヘルスチェックが失敗しタスクが登録解除される。ALBのヘルスチェック感度とCloudFrontフォールバック動作を検証する。

⏹ Stop: ALB 5xx > 50/分 CWアラーム
