CloudFront → API Gateway → Lambda → DynamoDB

AWS Fault Injection Simulator — 4 chaos scenarios targeting the serverless request path

B-1 DynamoDB Internal Error

Injects InternalError into every DynamoDB API call made by the Lambda execution role for 5 minutes (all of GetItem, PutItem, DeleteItem, Scan).

What to verify: Lambda retry/backoff logic, clean API 500 propagation to clients, CloudWatch alarm activation.

target aws:iam:role (Lambda exec role)   action: inject-api-internal-error

B-2 DynamoDB Write Throttle

Injects ProvisionedThroughputExceededException into PutItem and DeleteItem for 5 minutes. Reads (GetItem/Scan) remain healthy.

What to verify: Write-path circuit-breaker patterns, graceful read-only degradation, correct 429 surfaced to callers.

target aws:iam:role (Lambda exec role)   action: inject-api-throttle-error

B-3 DynamoDB Read Throttle

Injects ProvisionedThroughputExceededException into GetItem and Scan for 5 minutes. Writes (PutItem/DeleteItem) remain healthy.

What to verify: Read-path cache fallback or degraded-mode response, 429 propagation, Lambda error-rate alarm trigger.

target aws:iam:role (Lambda exec role)   action: inject-api-throttle-error

B-4 Lambda Concurrency Exhaustion

Sets the Lambda function's reserved concurrency to 0 for 5 minutes. All new invocations receive TooManyRequestsException immediately.

What to verify: API Gateway error mapping (429→502), CloudFront custom error page activation under sustained 5xx traffic.

target aws:lambda:function   action: put-function-concurrent-executions
